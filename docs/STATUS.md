## 这次解决的启动差异

只向命令行 URL 添加 ?game=/Script/Engine.GameMode，仍复现 0x7868802 的 EXCEPTION_INT_DIVIDE_BY_ZERO。把查询附在 GameDefaultMap 中也没有改变该结果；随后只读核心快照确实读回了带查询的字符串，但这不代表类选择已使用查询。

保留干净的 GameDefaultMap 包路径，将 ?game=/Script/Engine.GameMode 写入 LocalMapOptions 后，对照运行没有再发生该异常，并观察到原生地图画面。GameInstance 启动函数 0x43c4b60 的已有反编译显示默认地图与 GameMapsSettings 的附加字符串字段一起形成启动 URL；运行结果支持该配置路径有效。此结果仅适用于本机固定版本与基础模式，没有修复原 ShooterGameMode 的生命周期。

基础模式的日志没有输出 MapLoadModel/LogWorld 就绪事件，因此自动报告仍为 blocked_or_unproven，诊断返回 1。视觉证据与日志证据分别保存，未将存活时间、退出码或启动参数改判为训练完成。返回 2 表示执行或前置检查失败。

新 navigation 模式另有只读对象链判定，可确认目标世界和 Pawn，不再依赖缺失的日志事件。导航检查返回 0 也不表示完整训练可用，详细范围见 DUEL1.md。

## 原玩法剩余问题与接续点

原玩法的历史崩溃在 ServerMovementTimingComponent::BeginPlay 读取 FixedMoveTimeStepManagerComponent 的实际时步频率时发生，字段仍为零。静态构造默认值为 target=128、actual=0，管理组件自己的 BeginPlay 原本包含补为 128 的逻辑；尚需确认 GameState 与 GameMode 的实际初始化顺序。完整字段和调用链证据见 reports/native-map-init-crash.json。

1. 保留已经能显示场景的 scene 对照，继续观察原玩法下 GameState、固定时步组件和角色的生命周期。不能把修改除数当作完整修复。
2. 确定可工作的原生 PlayerController/Pawn 创建与输入路径；确认世界、类、实例及初始化完成状态。
3. 逐步接入原枪械、射击与机器人，再按 REQUIREMENTS.md 验收移动、命中、伤害、动画、声音和随机目标。
4. 游戏当前未证明有可用的原生 SpawnBot 路径，已分析的三个空实现不能作为生成器。

账号登录始终禁止。本轮未修改安装 EXE，测试只结束自己创建的游戏进程。日志中组件 BeginPlay 警告和 UI 路由警告仍保留；场景能显示不表示原 UI/小地图功能已初始化。
