请在 F:\valoranttrainer 项目的个人乱斗模式中，开发一套不同段位、各方面实力和习惯均可独立调整的人机系统。

请直接在现有项目中调查、设计、实施和验证，不要只输出方案或停留在示例代码。目标是让人机能够根据自己感知到的局面，像不同水平、不同习惯的真实玩家一样进行游走、搜点、预瞄、拉出、对枪、换位和应对突发情况。

本任务涉及的每项能力、动作、判断和习惯，落实到代码后都必须有能调节具体数值的设置。不要只提供一个总难度，也不要只为七大类各提供一个笼统滑条。

一、开始前：调查项目和厘清事实

1. 先阅读项目实际代码、文档、配置、WebUI、现有测试和运行验证方式，重点包括但不限于：

   - native/training_bot_controller.h
   - native/local_server_match.h
   - native/local_server_combat.h
   - native/training_world_geometry.h
   - tools/training_settings_v2.py
   - tools/training_control.py
   - 当前 WebUI 中的人机和乱斗设置
   - docs/STATUS.md、docs/IN_PROGRESS.md
   - reports/training-bot-controller.json
   - 与地图、武器、伤害、声音、出生、重生、原输入和验证相关的代码

2. 以上路径是调查起点，不保证覆盖所有调用链。以当前实际代码为准，区分：

   - 代码中已经存在什么；
   - 文档或历史报告声称验证过什么；
   - 当前版本实际运行时验证了什么；
   - 仍然需要开发或研究什么。

3. 特别调查当前乱斗模式实际使用哪条人机调度和原输入提交路径，避免创建第二套互相冲突的调度器。

4. 调查角色视角、可见性、碰撞与地面、移动速度、蹲跳、武器类型、弹药、真实开枪、受伤、死亡、重生、声音等信息分别能否稳定读取或感知。

5. 如现有数据源不足，继续调查并实现必要的数据接入。无法可靠获取的信息要明确标记限制，并继续完成不依赖它的部分；不能假装已经实现。

6. 阅读下方教学资料，也可以继续搜索其他高质量教学。资料用于理解动作和判断，不代表某个作者的教学是唯一正确打法，也不能替代当前客户端的实际验证。

二、总体目标与设计原则

1. 人机不是单纯的“反应时间 + 命中率”。每个人机应有独立的：

   - 瞄准能力；
   - 射击节奏和习惯；
   - 身法；
   - 身位控制与选位；
   - 预瞄和准星摆放；
   - 注意力；
   - 不同情境下的反应；
   - 信息获取、记忆、判断和决策；
   - 乱斗中的行动风格。

2. 支持从低到高的段位风格预设，也支持在预设基础上单独修改各项能力。例如：

   - 一次定位很快，但二次微调不准；
   - 架枪反应快，但被偷背身后转身慢；
   - 枪法好，身法一般；
   - 会广西步但不经常用；
   - 喜欢两连发，但遇到近距离时更容易扫射；
   - 有很好的预瞄，但注意力不够稳定。

3. 段位预设应是一组可编辑参数的组合，不应强制把所有能力绑在一起。没有足够真人对照数据时，只能称为“段位风格预设”，不能声称精确复刻某段位的平均水平。

4. 人机应主要根据自己能看到、听到、受到的反馈和记住的信息行动。项目底层可能能读取所有角色的状态，但不能让普通拟人模式的人机直接使用它本不应知道的敌人实时位置。

   - 敌人离开视野后，只保留最后一次合理获得的信息，并随时间降低可信度。
   - 受伤事件内部即使含有攻击者身份，也不能因此自动获得隔墙后的实时位置。
   - 允许根据已知信息进行合理推测，也允许误判。
   - 特殊训练功能如有必要，可以单独设计明确标识的模式，但不要把它混入默认拟人行为。

5. 保持项目现有的真实角色输入、武器、移动、射击、伤害和重生流程。人机能力应通过感知、决策和输入行为体现；如果需要改变游戏规则，必须在配置中明确标识，不能偷偷改伤害或伪造命中。

6. 人机不能只是随机播放大拉、蹲、跳等动画。每种动作都要有：

   - 使用它的条件和目的；
   - 实际可执行的动作过程；
   - 对应的数值设置；
   - 与瞄准、射击及其他动作的配合；
   - 执行失败或局面改变时的处理。

7. 允许稳定习惯和短时状态同时存在：

   - 稳定习惯：如喜欢点射、常用小拉、惯用横移节奏；
   - 短时状态：如注意力、当前信息、弹药、受击、当前移动速度。

   同一人机的能力和习惯应跨死亡重生保持稳定；行为上的适度变化应可复现。

三、感知、信息与记忆

先建立各人机独立的信息模型，作为后续所有决策的输入。

1. 视觉：

   - 根据人机实际视角、距离、遮挡、目标露出部位和露出时间判断是否发现目标。
   - 区分视野中心和边缘的发现能力。
   - 区分只露出头、只露出部分身体和大部分身体可见的情况。
   - 目标短暂闪过时，不应保证一定被识别。
   - 调查现有从眼睛到眼睛的单条视线检测能否满足要求；如不足，扩展并验证可见部位检测。

   可调：水平/垂直视野、视野边缘发现能力、距离影响、露出面积或程度的识别门槛、识别延迟和失误。

2. 听觉与受伤：

   - 调查能否感知脚步、枪声、落地和其他对乱斗有意义的声音。
   - 根据信息来源估计方向、远近和可信度，不默认知道精确位置。
   - 被击中后，分别处理“察觉受伤”“判断方向”“寻找攻击者”。
   - 如暂时不能稳定接入某类声音，明确说明并继续调查；不要以全图位置读取假装听觉。

   可调：各类声音的感知能力、判断延迟、方向和距离误差、漏听/误判概率、受伤后的方向判断能力。

3. 记忆：

   - 记录最后观察到的目标位置、时间、移动方向和信息来源。
   - 敌人离开视野后，随时间增加位置不确定性。
   - 已检查的角度也会随着时间重新变得不确定。
   - 目标死亡重生后，清理与旧角色生命周期不兼容的信息。

   可调：记忆时长、信息可信度衰减、位置估计误差增长、丢失目标后的继续架枪或搜索倾向。

四、瞄准能力

将一次定位、二次定位、微调、跟枪和架枪分别实现并独立设置。

1. 一次定位：

   - 发现目标后，将准星从当前位置移动到目标附近。
   - 允许定位不足、过冲或准确落点。
   - 根据目标距离、视角转动角度、目标移动及自身移动体现差异。

   可调：开始定位的延迟、转向速度、加减速、水平和垂直误差、过冲/欠拉概率及幅度、移动状态下的额外误差。

2. 二次定位与微调：

   - 一次定位未对准时，根据人机重新感知到的偏差进行修正。
   - 大偏差可进行二次定位，小偏差进行微调。
   - 修正可以不完美，也可以需要多次。
   - 目标消失、移动或出现更高威胁时，可以中断或改变修正。

   可调：二次定位启动延迟、速度与误差、微调速度、微调精度、抖动、修正次数、修正稳定性。

3. 跟枪：

   - 跟随横移、变向、蹲起、跳跃和落地的目标。
   - 自己移动时和站定时的跟枪能力应可不同。
   - 对目标变向应基于实际可见运动作出有延迟的反应，不能预知真实未来动作。
   - 目标短暂被遮挡后，按记忆和重新发现过程处理。

   可调：跟枪延迟、变向识别延迟、水平/垂直跟枪误差、跟随平滑程度、短暂失去目标后的重新发现能力。

4. 目标切换：

   - 对枪中第二个人出现，或击杀后需要面对另一人时，分别处理发现、判断、切换和定位。
   - 不应瞬间切到人机无法感知的目标。

   可调：目标切换判断延迟、切换转向速度、切换后的落点误差、继续打原目标或切换的倾向。

5. 架枪瞄准：

   - 区分预先架好的准星位置、发现敌人的反应、架枪时微调、实际开枪。
   - 架枪反应不等同于大角度转身反应。

   可调：准星稳定程度、架枪目标出现后的反应、近准星微调能力、架点偏差、敌人快速出人时的修正能力。

五、射击节奏、武器和对枪处理

1. 实现可配置的射击习惯，包括但不限于：

   - 单点；
   - 两连发；
   - 多发短点；
   - 持续扫射；
   - 近距离移动射击；
   - 打中后继续射击或停枪重置。

2. 决策应考虑武器类型、距离、目标暴露程度、目标与自身移动、当前准星位置、剩余弹药、武器状态及该人机的习惯。

3. 不同武器、不同距离可以使用不同的射击习惯，但不要硬编码“高水平人机必须统一采用某一种打法”。

4. 移动停止与武器射击恢复是不同状态；不要因为角色已经停下，就直接认定武器已恢复。

5. 尽可能根据真实开枪事件或可靠反馈统计弹数。不能仅把固定按住开火的时间直接声称为精准“两连发”。如果某种武器无法可靠统计，需要明确限制并继续研究。

6. 实现扳机纪律和预开枪：

   - 判断是否等待瞄准更充分；
   - 判断是否因为紧迫情况提前开枪；
   - 根据近期看到、听到或对常见点位的推测进行预开枪；
   - 预开枪不应依赖看不见的敌人实时坐标。

7. 实现命中和受击后的应对：

   - 是否识别自己打中了目标；
   - 是否继续连射、停枪、移动或撤退；
   - 目标死亡后停止射击并重新观察；
   - 受击后的移动变化、视角影响和重新瞄准按实际客户端机制处理。

8. 可调数值至少包括：

   - 各武器、距离和局面下各种射击方式的使用权重；
   - 每轮弹数或弹数分布；
   - 首枪等待、轮次间隔、停枪后开火时间；
   - 可接受的准星偏差；
   - 提前开枪、犹豫、预开枪的倾向和时机；
   - 目标消失后的停火延迟；
   - 命中确认延迟和误判；
   - 纵向/横向压枪能力及误差；
   - 弹药不足时的换弹阈值和找掩体倾向。

六、身法与对枪过程

动作的“使用倾向”和“执行能力”必须分开配置。

1. 摆射：

   - 横移、减速或停下、射击、再次移动。
   - 根据空间、距离、武器、对手动作和自身准星状态选择动作。
   - 不要固定每次严格左右交替。

   可调：横移距离、方向偏好、同向再次移动概率、停顿、开枪时机、每轮弹数、下一次移动启动时间。

2. 点蹲：

   - 在不同对枪时机短暂下蹲，再站起或衔接横移。
   - 下蹲不应永远机械地绑定开火。

   可调：使用倾向、触发时机、持续时间、连续点蹲间隔、站起延迟、与横移和开火的时间关系。

3. 广西步：

   - 调查具体教学和示例，将其实现为可调的横移、点蹲、摆射与瞄准配合，而不是只给一个名字或固定动画。
   - 支持变化，不要把它写死成永远相同的一组按键。
   - 保留对具体定义和不同教学版本的说明。

   可调：横移步长、换向节奏、下蹲触发时机、持续时间、开火与移动的配合、组合长度、变化程度、执行失误。

4. 死区射击：

   - 横向换向时，根据实际速度或经过验证的武器状态判断可尝试射击的时机。
   - 不要只根据“按下反方向”就假定进入了正确射击窗口。
   - 调查和验证当前客户端的实际运动与武器机制。

   可调：换向时机、射击触发阈值或时机、提前/延后误差、单次弹数、换向后继续移动的距离、失误率。

5. 拿信息的 peek、跳 peek：

   - 区分短暂观察后回掩体，与拉出去准备对枪。
   - 跳 peek 需要考虑起跳点、空中移动、视野是否真的越过掩体、落地和回撤。
   - 取得信息后，根据局面选择架枪、再次拉出、撤离或直接对枪。

   可调：使用倾向、探出距离、暴露时间、起跳时机、空中方向、回撤时机、发现目标后各后续动作的倾向。

6. 移动和瞄准协调：

   - 支持移动中提前调整准星。
   - 停下后可以立即开枪、先微调，或继续移动。
   - 第一轮没打中后，应能选择继续射击、横移重置、蹲下或回掩体。
   - 对不同动作的切换要有延迟和失误，不应每次都做出完美决策。

   可调：移动中瞄准精度、动作同步能力、首轮失手后的动作权重、反复左右移动的节奏变化、受击后调整动作的速度。

七、身位控制、搜点、选位与多人交战

1. 调查并建立必要的地图空间理解：

   - 可走区域及碰撞；
   - 掩体、掩体边缘、可能的退路；
   - 可观察角度和潜在威胁方向；
   - 角色在不同位置的暴露情况；
   - 高低差、箱子、门口、墙角等对视线和移动的影响。

   优先复用项目已有导航、碰撞、地面和视线查询。自动识别不可靠时，设计可维护的地图标注或校验机制，并说明覆盖范围。

2. 拆分枪线和搜点：

   - 根据当前视野、已知信息和地图结构，选择接下来需要检查的角度。
   - 尽可能逐步检查，而不是默认同时暴露在所有潜在方向。
   - 搜点顺序、移动幅度和准星应相互配合。
   - 已检查的方向不能永远视为安全。

   可调：搜点顺序偏好、每一步露出幅度、停留时间、风险权重、检查遗漏率、已检查角度的遗忘速度。

3. 同时遇到多人：

   - 判断当前目标、另一目标的威胁、可用掩体和退路。
   - 可选择继续打当前目标、切换目标、移动拆线或撤回。
   - 需要经过发现与判断过程，不能全知瞬切。

   可调：目标优先级权重、补枪/第三人发现速度、切换目标延迟、继续对枪倾向、撤退倾向、容忍同时面对多人的风险程度、误判概率。

4. 架枪位置：

   - 判断架哪个方向、在何处架、是否有退路、是否暴露给其他方向。
   - 支持常规位置和非常规位置。
   - 暴露或击杀后可选择保持、换位或重新搜索。

   可调：站位偏好、距离掩体的偏好、架枪时长、常规/非常规点位倾向、击杀后换位概率和延迟、侧背风险关注程度。

5. 抢线、推进与时机：

   - 根据听到或看到的信息选择主动推进、等待、绕路或占据有退路的位置。
   - 对敌人的武器状态和行动只能作合理推测，不直接读取人机不应知道的隐藏状态。

   可调：主动找人倾向、推进速度、等待时机的耐心、听到交战后的接近倾向、安全与进攻的权重、误判时机概率。

八、拉出掩体的方式和判断

至少覆盖：

- 大拉；
- 小拉；
- 一点点慢蹭；
- 跳拉；
- 蹲拉；
- Poppin swing；
- 肩探/骗枪；
- 拿信息后再次拉出。

对每种方式，都需要实现完整过程：

1. 拉出前：选择起始站位、目标角度、预瞄位置和目的；
2. 拉出时：根据动作控制移动、姿态和视角；
3. 拉出后：判断看到什么、是否开枪、继续扩大身位还是回撤；
4. 后续：决定继续架枪、换位、再次拉出或检查其他方向。

选择时考虑：

- 是否掌握敌人位置，信息有多可信；
- 武器与交战距离；
- 角度关系、可用空间和掩体；
- 是否可能同时暴露在其他方向；
- 人机的经验、习惯及当前注意力；
- 是否刚观察到或听到对方开枪。

每种拉法都要有独立的使用倾向、触发条件、距离、时机、动作精度和失误设置。

Poppin swing 不要简单实现成“普通大拉速度加倍”；应结合教学和实际验证拆出持续横移、跟枪、停下和开火的时机。广西步、Poppin swing 等名称存在不同用法时，应记录所采用的定义和参考示例。

九、预瞄与准星摆放

在没有看到敌人时也持续运行预瞄逻辑，而不是发现目标后才转视角。

1. 根据游走、接近转角、搜点、架枪或追击等状态，选择接下来关注的方向。
2. 考虑敌人可能出现的墙边、常见位置、距离和高低差。
3. 根据预计出人速度、架枪习惯和反应能力，决定准星离墙边的距离。
4. 移动过程中尽量维持或转移预瞄，但允许偏差、遗漏和错误预判。
5. 目标出现时，使用当前真实准星位置进入定位流程。

可调：头线高度误差、对高低差的修正能力、离墙距离、预期大拉/小拉的倾向、预瞄保持能力、转移预瞄速度、遗漏角度概率、错误预判概率。

十、注意力与情境反应

1. 注意力：

   - 模拟集中、正常、走神和恢复等状态，具体状态数量可根据实现设计。
   - 注意力会影响发现、判断和操作，不应只是固定额外延迟。
   - 持续架枪、长时间无事、突发声音、受伤和交战等可以影响注意力。
   - 强的人也可能偶尔愣神，弱的人也可以注意力较好。

   可调：走神频率与持续时间、状态转换速度、对视觉和决策的影响、受击或声音后的恢复速度、紧张时的失误倾向。

2. 分开实现不同情境的反应：

   - 架枪时敌人出现；
   - 主动拉出后遇敌；
   - 对枪中出现第二人或遭到补枪；
   - 被侧面或背身偷袭；
   - 听到声音后的反应；
   - 受伤后的反应；
   - 目标消失后再次出现；
   - 目标突然变向、下蹲或跳起。

3. 将反应拆为“事件发生 → 察觉 → 判断 → 开始动作 → 动作完成”，避免重复叠加延迟或用一个总值代替所有过程。

4. 被偷背身时，至少区分：

   - 察觉受伤或声音；
   - 估计方向，允许出错；
   - 决定先转身还是先找掩体；
   - 开始并完成转视角；
   - 重新发现敌人；
   - 定位和开枪。

5. 可调：各情境的发现和判断延迟、转身启动时间、转向速度、方向判断误差、目标切换延迟，以及不同情境下的犹豫和失误。

十一、乱斗玩法和个人风格

在个人乱斗中实现并允许调节：

- 主动找人或守区域的倾向；
- 听见枪声后靠近、等待或回避；
- 架枪持续时间和换位频率；
- 胜负导向与主动找对枪的不同玩法倾向；
- 第三方交战的介入倾向；
- 打完一个人后检查其他方向、换位、换弹或继续推进；
- 低血量和低弹药时的风险判断；
- 复活后选择路线、恢复警戒和重新找人的行为。

这里的“补枪”要符合个人乱斗语境：人机可能在与一人交战时被第三人攻击，也可能听见两人交战后选择介入。不要把团队模式的协作逻辑直接套进自由混战。

十二、配置、预设和 WebUI

1. 上述每一项落地后的具体能力、动作和判断，都应有相应设置。不能只提供“瞄准 80、身法 70、战术 60”这样的笼统参数。

2. 每种技巧至少区分：

   - 是否启用；
   - 使用倾向或概率；
   - 在哪些局面下使用；
   - 动作本身的时间、距离、速度、弹数等；
   - 执行精度、失误和与其他动作的配合。

3. 各项能力要尽量独立。选择段位预设可以批量填入多个值，但手动修改某项时，不应无说明地改变其他能力。

4. 为参数提供清楚的：

   - 中文名称和含义；
   - 单位；
   - 合法范围；
   - 默认值；
   - 适用条件；
   - 生效时机；
   - 与其他参数可能存在的依赖。

5. 支持固定值以及需要时的波动范围。既可以做出稳定习惯，也能让行为有合理变化；同时支持通过种子复现。人机个体能力在同一对局跨重生保持稳定。

6. 提供从低到高的段位风格预设，并允许修改预设后的任意具体数值。不同人机应支持有个体差异；调查现有系统后设计全局配置、个体配置和分布配置，说明各自的优先级。

7. WebUI 中提供清晰的分组和说明，必要时提供常用设置与展开的详细设置，但不能把细项藏在不可修改的内部公式里。

8. 沿用项目现有的配置存储与传输链路，考虑旧配置迁移、默认值、参数校验和协议兼容；说明改动是当前对局立即生效还是下一局生效。

9. 如果游戏更新频率或可观测精度无法兑现某项设置的精度，必须在设计和界面说明，不能展示实际上不生效的精确数值。

十三、技术实现与验证要求

1. 设计清晰的人机状态和决策流程，至少覆盖：

   感知与记忆
   → 局面判断
   → 选择位置和动作
   → 预瞄或发现目标
   → 反应、瞄准、移动与射击
   → 根据命中、受击和局面变化调整
   → 交战后处理。

2. 明确不同模块对视角、移动、蹲、跳和开火输入的协调方式与优先级。当前动作必须能在受伤、目标变化、死亡、碰撞或更紧急情况出现时合理中断，避免输入冲突、卡住或持续误开火。

3. 使用原游戏的武器、角色和物理反馈验证动作。请求了蹲、跳、开火或移动，不等于游戏已经实际执行；需要观察实际结果。

4. 自动化验证应覆盖：

   - 参数边界与配置迁移；
   - 段位预设和独立参数；
   - 种子复现与重生后的能力稳定；
   - 视野、遮挡和信息过期；
   - 目标出现、消失、死亡和重新出现；
   - 各动作触发、阶段转换、中断与释放输入；
   - 多目标决策；
   - 可统计时的实际射击弹数；
   - 参数变化确实影响对应行为。

5. 在可用条件下进行真实游戏内验证，覆盖：

   - 静止、移动、变向、蹲起目标；
   - 单点、两连发、短点、扫射和失手后的行为；
   - 摆射、点蹲、广西步、死区射击；
   - 有真实掩体的各种 peek 和回撤；
   - 常规位、非常规位、拆线和多人交战；
   - 墙边预瞄和高低差；
   - 架枪、走神、偷背身、第三人出现；
   - 乱斗中的复活、游走、连续交战、死亡和重生。

6. 为每项关键行为记录可检查的证据，例如：

   - 事件发生、发现、判断、动作开始、实际开枪的时间；
   - 准星轨迹与目标相对位置；
   - 实际开枪数和间隔；
   - 移动速度、方向、蹲跳状态；
   - 选择了哪种动作及其原因；
   - 使用了哪条可见/听觉/记忆信息；
   - 实际结果和失败原因。

   日志应能帮助解释结果，同时注意多人乱斗时的性能。

7. 校准不同段位风格时，分别观察多项能力和对局表现。不要仅凭 KD、爆头率、单次演示或参数数值宣称人机已准确达到某段位。

8. 对实际环境无法完成的验证，报告原因、已完成的部分和具体缺口。不要把历史报告、模拟测试或编译成功写成当前版本真实对局已经通过。

9. 确保多人乱斗规模下感知、视线、地图查询和决策开销可控，验证不会导致明显卡顿；同时不要为了性能悄悄删掉要求的行为或让设置失效。

10. 完成后说明：

   - 实现了哪些能力和判断；
   - 每组设置在哪里；
   - 哪些功能经过了自动化测试和实际游戏测试；
   - 哪些地图、武器或情境尚未验证；
   - 当前限制；
   - 段位预设的校准依据；
   - 配置迁移与生效方式。
